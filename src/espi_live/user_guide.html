ESPI live — User Guide

ESPI live shows a live image from a FLIR Blackfly BFS-U3-63S4M-C Mono8 camera (or an analog camera through a capture adapter) and turns it into ESPI (electronic speckle pattern interferometry) measurements by subtracting frames. This guide explains every control and walks through the operations you will use most.

Offline guide Open from Help → User Guide (F1) Links work in this page

Quick start #

  1. Start the app with a camera connected (or choose demo mode when asked).
  2. Stay in Raw view and position and focus the specimen.
  3. Adjust Exposure so the image is bright but not washed out. Use Gain only when exposure is not enough.
  4. Switch to Reference and press F (or Set reference) with the specimen in its resting state. Detailed steps.
  5. Load or deform the specimen. The difference image shows the ESPI fringe pattern.
  6. If the pattern is noisy, raise Average N. If it is faint, leave Stretch to 0–255 on and try a color Palette.
  7. Press S (Save frame) to keep a still, or Record AVI to capture a sequence. Add a title and notes before saving to identify the measurement.

Starting the application #

With a camera #

On the Windows camera PC, double-click scripts/windows/SETUP AND START ESPI.bat. It checks Python, OpenCV, NumPy, PySide6, PySpin and the Spinnaker SDK, asks before installing anything, and launches the app when validation passes. After an install, close any installers and run the same file again.

On macOS or Linux, from a terminal in the project folder:

./run.sh

On Windows, from the project folder in a command prompt:

set PYTHONPATH=src
python -m espi_live

The app opens the first FLIR camera it finds. If no camera is detected, it offers to start demo mode; choose No to quit instead.

Without a camera (demo mode) #

./run.sh --demo

Demo mode produces a moving synthetic grayscale pattern, so you can learn the controls, check processing, and test saving and recording without a camera. Exposure, gain and frame rate are simulated.

Demo data is clearly marked. A red DUMMY MODE banner (in the Controls panel) and a status badge are visible, and every saved frame and recording carries a DUMMY MODE ACTIVE watermark and a dummy_ filename prefix. Demo data is never presented as camera data.

Demo frames are 960×640. The watermark covers the top ~10% (at least 42 px), so that band is hidden in demo previews, saved frames and recordings.

Command line #

There is one Qt front end. Useful options:

  • --demo — synthetic video without touching a camera; --demo-cameras N creates several synthetic cameras.
  • --check — load every module without opening a window and exit. --version prints the build number.
  • --update — install the newest full release without opening a window. --no-update-check skips the startup update check and the source download.
  • --send-changes — send changes made in the downloaded source folder (see Updates, features and Codex).

Controls reference #

Demo banner and Switch to live capture #

These appear only in demo mode.

  • DUMMY MODE banner and badge: a reminder that the image is synthetic.
  • Switch to live capture: retries camera detection without restarting the app. If a camera is found, the app resets to Raw view, clears measurement baselines, stops any demo recording, and continues with live frames. If no camera is found, a warning explains why and demo mode keeps running.

Toolbar #

  • View modes — Raw, Previous and Reference; see View.
  • Record AVI — start or stop recording the displayed image. The recording label shows the output rate.
  • Freeze (Space) — hold the displayed image without saving it. The camera keeps acquiring, averaging, reference refresh and recording continue. An amber FROZEN bar over the image and a status badge mark the held frame; press Space again to return to live. Save frame saves the held image, and Set reference still uses the live camera frame.
  • Save frame (S), Set reference (F), Reset last (R), Reset average (A) — the same actions as the measurement and capture sections.
  • Zoom — drag, click or scroll the slider to zoom from fit (100%) up to 64×; Fit (0) and 1:1 (1) jump to those levels. The mouse wheel zooms around the cursor and dragging pans.

Every control, menu item and status readout has a hover tooltip that explains it. Tip text waits briefly so it does not flicker as the pointer moves.

View #

Choose how each frame is built. All three modes use the same camera frames; with Average N = 1 they update at the same rate. With N > 1, Previous and Reference publish a new image only after N frames.

Raw

The direct Mono8 camera image with no subtraction, stretch or palette; the gamma slider still applies. Use it for positioning, focusing and checking exposure.

Previous

The absolute difference between this frame and the previous one. Stationary areas are black; anything that changed since the last frame is bright. The first frame after switching becomes the baseline and displays black.

Reference

The absolute difference between this frame and a stored reference frame. Capture the resting state once, then watch how the specimen changes against it. Until a reference exists, the view is black and a hint tells you to press F.

Changing the view mode clears any partial average. Switching to Previous starts a fresh baseline on the next frame. The reference frame is kept until you capture a new one, switch to live capture successfully, or close the app.

Below the view buttons, a hint line describes the current mode and reminds you when a reference is still needed.

Camera #

  • Exposure (microseconds) — how long each frame collects light. It changes brightness and motion blur. The default is 8000 µs. Longer exposure means a brighter image but limits the maximum frame rate.
  • Gain (dB) — electronic amplification. It brightens the image but also amplifies noise, so prefer more exposure when the specimen allows it. The default is 0 dB.
  • Requested FPS — the frame rate you ask the camera for. The default is 30 fps. The camera may deliver less if exposure, USB bandwidth or the camera's own limits prevent it.
  • Noise reduction — blends each camera frame with the previous ones (0 = off, 95 = strongest; each step adds the same amount of memory, so 10 keeps about three frames and 95 about twenty) to remove random sensor noise in every view, Raw included, while keeping the speckle ESPI fringes depend on. Higher values smooth more but leave a trail behind motion and weaken Previous-view fringes; a Reference captured with it on is less noisy too.
  • Single field (interlaced camera) — shown for an interlaced analog source; on by default. It keeps one field, doubled to full height, removing the 1/60 s offset between fields at the cost of half the vertical detail.

Each control has a slider for quick changes and a number box for exact entry: drag the slider, type a value and press Enter, or use the arrow keys.

When a camera is connected the sliders adapt to its readable limits, but this build clips them to 0–50,000 µs exposure, 0–30 dB gain and 0–60 fps. The camera itself can reach 30 s and 47.99 dB, but those values are not exposed in the UI. Out-of-range values are clamped. The 100 ms frame-grab timeout also means very long exposures can stop the stream from keeping up.

Each time the app opens the camera it writes Mono8, continuous acquisition, auto-exposure and auto-gain off, 8000 µs, 0 dB and 30 fps, and selects NewestOnly buffering. Settings made in SpinView are replaced; set exposure, gain and frame rate in the app.

Rate limiting and the readout

Changes are sent to the camera at most about ten times per second, so dragging a slider stays smooth. The readout underneath the controls is refreshed once per second and shows:

Applied: 8000 µs, 0.0 dB; FPS set 30.0, resulting 29.8
  • Applied is what the camera actually accepted, which can differ from what you requested if the camera clamped a value.
  • FPS set is your request; resulting is the measured acquisition rate. A lower resulting rate is normal at long exposures or high resolution.

In demo mode this readout says that exposure, gain and FPS are simulated.

See Adjust exposure, gain and frame rate for practical steps.

ESPI measurement #

These controls apply to Previous and Reference views. Raw ignores them.

  • Average N — each displayed image becomes the mean of N consecutive difference frames. Averaging reduces random noise at the cost of a slower displayed update: at 30 fps and N = 5, a new averaged image appears about six times per second. While the first N frames are collected the image stays unchanged, and changing N or the view mode restarts the count. Recording follows the averaged rate.
  • Rolling average (updates every frame) — a running average that still updates at the camera rate. Use it when you want to watch fringes move instead of waiting for each block of N frames.
  • Ref. refresh — Reference view recaptures the reference every N seconds so slow drift (air currents, heat) cancels; 0 keeps one reference until you press F.

Fringe enhancement #

  • Speckle filter — Gaussian, or edge-keeping Median (capped at 5 px to keep the frame rate). Use Median when a wide Gaussian blurs fringe edges.
  • Filter width — blur in pixels that removes pixel-scale speckle; keep it well below the fringe spacing. 0 = off. A typical start is 0, then a few pixels.
  • Stretch to 0–255 — maps each difference frame's darkest and brightest pixels (after Stretch clip) to 0 and 255, so fringes fill the display. The status bar shows the input and scaled ranges, before gamma and palette. A constant difference image maps to black.
  • Stretch clip — lets this percentage of the darkest and brightest pixels saturate so a few stray speckles do not flatten the contrast; 0 = exact min/max, about 0.5% when a few speckles dominate.
  • Invert — swaps bright and dark fringes.

Stretch, clip and invert apply to difference views; Raw is never stretched or inverted.

Display #

These controls apply to Previous and Reference views. Raw always shows untouched grayscale.

  • Palette — Gray, Turbo, Jet, Hot, Viridis, Plasma or Inferno. Color palettes make small intensity differences easier to see. The palette applies to the whole processed frame, and saved files and recordings use exactly the same colors as the screen.
  • Gamma — a display curve from 0.1 to 3.0. Values below 1 darken midtones and values above 1 brighten them. Gamma does not change the measurement data, only how it is displayed and saved. 1.0 leaves the image unchanged.
  • CLAHE (color palettes only) — contrast-limited adaptive histogram equalization. It boosts local contrast in small tiles, which can reveal faint fringes in unevenly lit areas. It is computed on the CPU, so it costs more processing time, and it is ignored when the palette is Gray. Gamma is applied before CLAHE.

See Get the best contrast.

Capture and saved frames #

  • Record AVI — when checked, writes the displayed image to an AVI file at a steady output rate. In Previous/Reference the output rate is the source rate divided by Average N, capped at 30 fps and floored at 1 fps. In Raw view Average N is ignored. Recording includes the palette, gamma, CLAHE, scaling and, in demo mode, the watermark, so the file matches the screen. The label beside the button shows the output rate, and recording continues while you move, resize or interact with the window.
    • If encoding cannot keep up, intermediate preview frames are skipped and the AVI timeline still advances; when acquisition is slower than the output rate, the last frame is repeated. The log reports skipped frames and late encoder intervals when the file is closed.
    • Changing the view mode, or Average N or Rolling average in Previous/Reference, closes the current AVI and starts a new one. Other changes do not split the file: palette, gamma, CLAHE, Stretch to 0–255, Stretch clip, Speckle filter, Invert, exposure, gain, FPS, noise reduction, Single field, Set reference, Reset last and Reset average all continue writing to the same file. Stop and restart the recording after any of them, or the file will mix processing configurations or measurement baselines.
    • Unchecking Record AVI finishes the file cleanly. Closing the app also finishes it, waiting up to about 5 seconds for the writer; the log prints the final path and frame count.
  • Title (optional) — a short label added to the saved PNG filename. Characters that are unsafe in filenames, including spaces, become underscores; leading/trailing underscores are removed and the result is limited to 80 characters.
  • Notes (optional) — free text stored in a sidecar .txt file next to the PNG. When the display is frozen, the sidecar also records when it was frozen.
  • Save frame (S) — saves exactly what is on screen as a PNG. If no display frame is ready yet, the log says No current display frame is ready to save. If a title or notes are present, a .txt file with the same base name records the title, notes and whether the source was the camera or demo mode.
  • Set reference (F) — stores the current live camera frame as the reference and resets averaging. This is the same reference used by Reference view; when the display is frozen, Set reference still captures the live camera frame, not the frozen image.
  • Reset last (R) — forgets the stored previous frame. Previous view then starts a fresh baseline on the next frame (with Average N = 1 that is one black frame before differences resume; with N > 1 the first displayed image is an average that includes it). It does not affect the reference.
  • Reset average (A) — discards a partial average. The next displayed image restarts the N-frame count. Useful after a disturbance so one disturbance does not smear into the next measurement.

Before you record: in Reference view, confirm a reference exists and the image is not black; in Previous view, wait for the first baseline frame. A recording started before either exists contains black frames. Stop the recording before changing exposure, gain, FPS, palette, gamma, CLAHE or scaling, or before Set reference, Reset last or Reset average. Check free disk space first: the AVI is full-resolution MJPG, there is no size limit or free-space check, and a full disk stops the recording.

See Save a still frame with notes and Record a measurement sequence.

Status bar #

From left to right:

  • View hint — a short reminder for the current mode, such as pressing F for a reference.
  • FROZEN badge and the amber FROZEN at time over the image — the display is held; the camera and recording continue.
  • Source badge — green Camera for live acquisition, red DUMMY MODE for synthetic video.
  • Recording state — off, or the AVI output rate while recording.
  • Measurement range — for difference views, the input minimum and maximum and the scaled range, for example Input: 3–41 Scaled: 0–255. In Raw view it reads Raw Mono8: no brightness scaling. The range is measured after Stretch clip and before gamma, CLAHE and the palette.
  • Processing and display rate — Processed: 29.9 fps Work: 4.2 ms/frame followed by Displayed: 29.8 fps. Processed is the rate at which the worker acquired and processed frames; Work is the average processing time per frame. Displayed is the rate at which the window actually repainted. With Average N = 1, a lower displayed rate than processed rate means the display or window compositor is the bottleneck. With N > 1 (and Rolling average off), Displayed is expected to be about Processed/N because a new image is published only after N frames.
  • Pixel readout — while the pointer is over the image: x 412, y 208: 137, the image coordinates and the 0–255 sample used for display: after Stretch clip and scaling, and after gamma/CLAHE when CLAHE is on. With scaling off it is the raw absolute difference. It is not calibrated in physical units.
  • Update / feature buttons — Check for updates (or the blue Update available button), Request feature and Open in Codex. See Updates, features and Codex.

Log panel #

The log is the application's record of what happened. It is timestamped and scrolls automatically. It reports startup and streaming, camera timeouts and failures, view changes, every saved file and its path, recording start and finish with frame counts, averaging and reference actions, demo/live switches, and errors. Applied camera settings are shown in the camera readout beneath the controls, not in the log.

Each run writes output/logs/espi_<YYYYMMDD_HHMMSS_microseconds>.log. When reporting a problem, include the relevant lines from this panel or that file.

The log keeps the most recent 2000 lines in the window; the file keeps the full run. Lines from several cameras start with the camera's serial number.

If output/ is not writable (for example the app is in a protected folder), no log, frame or recording file can be written. The log panel and console remain, but move the app to a writable folder to capture files.

View menu #

  • Controls, Log and the toolbar — show or hide each.
  • Fit to window (0) — show the whole image, aspect-correct. Actual size (1) uses one camera pixel per screen pixel.
  • Freeze display (Space) — hold the displayed image without saving it; the camera keeps running.

Docks can also be dragged by their title bars. Dropping one outside the main window floats it; closing a dock hides it. The layout is saved on exit. The menu also lists the shortcut keys.

Help menu #

  • User Guide (F1) — opens this page in your default browser. Every section link and cross-reference works offline; the filter, theme and print controls are in the sidebar.
  • Check for updates… — check GitHub for a newer build and report the result in a dialog.
  • Request a feature… — file a GitHub issue with a title and optional description; see Updates, features and Codex.
  • Ask Codex about the source code… — open the build's source in OpenAI Codex.
  • About ESPI live — the build number and version of this copy.

Several cameras #

When more than one FLIR camera is connected, a Cameras section appears at the top of the Controls panel.

  • Display picks the camera shown in the window.
  • Each camera has a Process checkbox. A checked camera keeps acquiring, processing and recording while another camera is displayed. The displayed camera always processes, so its checkbox is locked on; choosing an unchecked camera in Display turns it on.
  • Each row shows that camera's processed rate and REC while it records.
  • Every camera has its own settings, reference, average, display options, freeze frame and Record state. Controls, the toolbar and shortcuts always act on the displayed camera.
  • Unchecking Process stops that camera (finishing its recording and releasing it) but keeps its settings for next time; its reference and running average start fresh. At startup only the first camera that opens is processed.
  • Log lines from each camera start with its serial number. An error in one camera turns only that camera off.

Several 6.3 MP cameras streaming at once can exceed one USB 3 controller's bandwidth. Watch each row's frame rate; lower the frame rate or use separate controllers if it drops. --demo --demo-cameras 3 simulates three cameras for trying this without hardware.

See Use several cameras.

Analog camera #

The Sony XC-ST50's composite video goes through a Hauppauge USB-Live2 into the PC, and the stick appears in the camera list as Hauppauge USB-Live2 (video N). Close WinTV and Hauppauge Capture first: the stick serves one program at a time.

  • Exposure, gain and frame rate are set by the camera's own switches, so those controls are disabled; the status line shows the measured capture rate.
  • Single field (interlaced camera), on by default, shows one of the two interlaced fields, doubled to full height. This removes the 1/60 s offset between fields at the cost of half the vertical detail.
  • Images look about 12% wide because NTSC pixels are not square; they are not resampled. Expect coarser fringes than with the Blackfly.

Other video devices (webcams, other capture sticks) are listed as not yet supported and are never opened unless you choose one. When you switch one on, it runs as delivered, and the viewer files a GitHub issue labelled camera-support with what the device reports, once per device type. A copy without a feedback token saves the report to output/logs/camera-report-*.md and shows a Report this camera button instead.

Common operations #

Position, focus and inspect the image #

  1. Select Raw view.
  2. Use Exposure and Gain to get a well-exposed image.
  3. Use the toolbar Zoom slider, or the mouse wheel or trackpad on the image, to zoom up to 64×. At high zoom individual pixels are shown sharply.
  4. Drag with the left mouse button to pan while zoomed.
  5. Double-click the image to toggle between fit and 4× zoom. Press 0 for fit and 1 for 1:1.
  6. Watch the pixel readout in the status bar to check individual values.

Freeze and inspect an image #

  1. Press Space or click Freeze. The image holds and an amber FROZEN at bar appears; the camera, averaging, reference refresh and recording keep running.
  2. Zoom, pan and read pixel values on the held image.
  3. Press S to save the held image; the sidecar records when it was frozen. Set reference still captures the live camera frame.
  4. Press Space again to return to live. With several cameras, each keeps its own frozen frame; switching a camera off or to live drops it.

Capture a reference and see a difference measurement #

  1. Put the specimen in its resting state.
  2. Select Reference view.
  3. Press F or click Set reference. The log confirms the capture, and the hint changes from asking for a reference to showing the difference view.
  4. Load, heat or otherwise deform the specimen. The image now shows absolute differences from the resting state.
  5. If the pattern is too faint, turn on Stretch to 0–255 and try a color palette.
  6. To start a new measurement from the current state, press F again.
  7. If the camera settings or illumination change, capture a new reference; otherwise the brightness change appears as a large false difference.

Measure frame-to-frame change instead #

  1. Select Previous view.
  2. The first frame becomes the baseline, then each displayed image is the difference from the frame before it. This is useful for spotting motion or vibration that is present right now.
  3. Press R (Reset last) after a disturbance to start a clean baseline.

Average and rolling average #

  1. Select Previous or Reference.
  2. Raise Average N. Start around 3–5 and increase until the fringes are stable; higher values mean a slower displayed update.
  3. Turn on Rolling average when you want a running average that still updates every frame, for watching fringes move.
  4. If a disturbance has just occurred and the image looks smeared, press A (Reset average) to restart the accumulation.
  5. For slow drift from air or heat, set Ref. refresh to a few seconds; 0 keeps one reference until you press F.
  6. Recording runs at the averaged rate unless Rolling average is on, so a large N produces a lower-frame-rate AVI with the same duration.

Reduce sensor noise #

  1. Raise Noise reduction in the Camera section to blend each frame with the previous ones (0–95%).
  2. Use the lowest value that cleans the background; high values leave a trail behind motion and weaken Previous-view fringes.
  3. Use Average N for difference-frame noise; these two controls solve different problems.

Get the best contrast #

  1. Keep Stretch to 0–255 on for a first look; the status bar shows the true input range.
  2. Choose a color Palette for small differences.
  3. Use Speckle filter and Filter width to blur away pixel-scale speckle; keep the width well below the fringe spacing.
  4. Set Stretch clip to about 0.5% when a few stray speckles flatten the contrast; 0 is exact min/max.
  5. Adjust Gamma to brighten or darken the midtones, and Invert to swap bright and dark fringes.
  6. Enable CLAHE if one area is much dimmer than another; it boosts local contrast but costs processing time and only works with a color palette.
  7. Turn Stretch to 0–255 off when you need to judge absolute difference values between frames; the status bar and pixel readout then show the unscaled values.

Save a still frame with notes #

  1. Type a Title, for example aluminium_plate_40C.
  2. Type any Notes: load level, temperature, specimen, lens, or anything needed to interpret the image later.
  3. Click Save frame or press S. If the display is frozen, the held image is saved and the sidecar records when it was frozen.
  4. The log shows the PNG path. If a title or notes were present, a matching .txt file holds them with the source (Camera or Demo).

The PNG contains exactly the current display, including palette, gamma, CLAHE, stretch, invert and the demo watermark.

Record a measurement sequence #

  1. Set the view, averaging, palette and contrast you want. These choices are baked into the recording.
  2. Click Record AVI. The status label beside the button shows the output frame rate.
  3. Perform the experiment. You can keep using the window while it records.
  4. Click Record AVI again to stop. The log prints the file path and a summary of frames written and skipped.
  5. Find the file under output/recordings/ (see Files and output folders).

Only the view mode, and Average N or Rolling average in Previous/Reference, start a new file. Changing palette, gamma, CLAHE, Stretch to 0–255, Stretch clip, Speckle filter, Invert, exposure, gain, FPS, noise reduction, Single field, Set reference, Reset last or Reset average continues the same file. Stop and restart the recording after any of those changes, or record them as separate files and note the change in your lab book.

Adjust exposure, gain and frame rate #

  1. Watch the Applied line under the camera controls.
  2. Increase Exposure for a brighter image and better signal-to-noise ratio, at the cost of motion blur and a lower maximum frame rate.
  3. Increase Gain only when exposure is already as long as the experiment allows.
  4. Set Requested FPS to the rate you need. If the resulting rate is lower, the camera, exposure or USB bandwidth is the limit.
  5. Raise Noise reduction only as needed; it cleans sensor noise in every view but trails motion and weakens Previous-view fringes at high values.
  6. For an interlaced analog camera, leave Single field on unless you need the full vertical detail and can accept the 1/60 s field offset.
  7. After changing camera settings, capture a new reference if you are measuring differences.

Arrange the workspace #

  • Drag the Controls or Log dock by its title bar to another edge or out of the window to float it.
  • Use View → Controls or View → Log to hide or show a panel.
  • Resize the window; the layout and size are restored the next time the app starts.
  • On a small screen, hide the log while measuring and show it when you need to check a saved path or an error.

Switch from demo to live capture #

  1. Connect and power the camera.
  2. Make sure no other application (SpinView, another viewer, a script) is using it.
  3. Click Switch to live capture.
  4. If it succeeds, the red indicators disappear, the view resets to Raw, and any demo recording is stopped so synthetic and live frames never share a file. The switch also configures the camera at 8000 µs, 0 dB and 30 fps. The sliders keep the demo values, so check the Applied readout and re-enter your exposure, gain and FPS before measuring. Capture a new reference before continuing.
  5. If it fails, a warning gives the reason and demo mode continues. Fix the connection and try again; no restart is needed.

Use several cameras #

  1. Connect the cameras. The Cameras section appears at the top of Controls when more than one source is available.
  2. Pick the camera to show with Display. The controls, toolbar and shortcuts act on that camera.
  3. Leave Process checked on cameras that should keep acquiring, processing and recording in the background.
  4. Watch each row's rate and REC marker. If rates drop, lower the frame rate or move cameras to separate USB 3 controllers.
  5. Uncheck Process to stop a camera and release it; its settings are kept, but its reference and average start fresh when it runs again.

Files and output folders #

Everything is written under the project's output/ folder. In a packaged build, that folder sits next to the executable (next to the .app on macOS).

output/
  logs/        one log file per run
  frames/      saved PNG stills and their .txt sidecars
  recordings/  AVI recordings

File names use the camera's serial number (when several are used) and a local timestamp:

  • Frames: frame_<serial>_YYYYMMDD_HHMMSS_microseconds[_title].png
  • Recordings: espi_<view>_<serial>_YYYYMMDD_HHMMSS_microseconds.avi
  • Demo files add a dummy_ prefix.
  • Logs: output/logs/espi_<YYYYMMDD_HHMMSS_microseconds>.log.

Recordings are MJPG-compressed AVI files. They are capped at 30 fps and use the same colors as the screen. A frame title or notes produce a sidecar text file with the frame name, source, title, notes and, for a frozen image, the time it was frozen.

Troubleshooting #

Click a symptom to expand it. The same information is in the log panel and the run's log file under output/logs/.

No camera was detected

The app offers demo mode. Check that the camera is powered, connected by a USB 3 port and cable, and not open in SpinView or another application. Then click Switch to live capture or restart the app. If PySpin is not installed, the log says so; on the camera PC run the setup script again.

Live capture switch fails

Read the warning dialog and the log. Common causes are another program holding the camera, a USB 2 port or hub, a loose cable, or a camera that has not finished booting. Demo mode keeps running so you can retry without losing the session.

The image is black in Previous or Reference view
  • Confirm a reference has been captured; the hint line says if one is missing.
  • With Stretch to 0–255 on, a constant difference image is all black by design. Disturb the specimen or turn stretching off to inspect raw values.
  • Check that the view is not Raw after a live-capture switch.

A recording started before a reference exists, or before the first Previous baseline frame, contains black frames. Stop it, wait for a real difference image, then start the recording.

The image freezes and the status bar says “Waiting for camera frame”

The app has stopped receiving valid frames. Check the USB 3 cable and port, close SpinView or any other application using the camera, and restart the camera or the app. The log repeats Camera timeout or acquisition error every few seconds. The app does not reconnect automatically.

The displayed rate is lower than the camera rate

Read Processed and Displayed in the status bar. If Processed is low, the limit is acquisition: exposure, USB bandwidth, or the camera. Average N does not lower Processed; it lowers Displayed (see below).

If Processed is high but Displayed is low and Average N is 1, the window or graphics system is the bottleneck; hide the log or reduce the window size. The CPU fallback is selected automatically when OpenGL 3.3 is unavailable; it is not a performance option.

At full resolution the camera is rated 59 fps for Mono8 and the app caps the requested rate at 60 fps. At 8000 µs the exposure is not the limit; longer exposures can reduce the attainable rate. Use the resulting FPS readout as the authoritative value.

The log says “Display: CPU fallback”

The machine could not create an OpenGL 3.3 core context, common in some remote-desktop sessions. Everything still works, but the CPU draws and scales the image, so the display rate may be lower and large windows cost more CPU.

Recording skips frames or repeats frames

The AVI is written on a constant-rate timeline because encoders and players expect one. If the encoder cannot keep up, preview frames are skipped; if acquisition is slower than the output rate, the last frame is repeated. Lower Requested FPS or raise Average N to reduce the output rate. The log reports skipped frames and late intervals when the file is closed.

Recording stops by itself

Changing the view mode or Average N closes the current file and begins a new one. An encoder error also stops recording and turns the button off; the log contains the reason and any path that was saved.

A control snaps back or will not reach the value I typed

The camera is clamping the value, or the value is outside this build's fixed UI limits: exposure 0–50,000 µs, gain 0–30 dB and Requested FPS 0–60. The camera itself can reach 30 s and 47.99 dB, but those values are not exposed here. Check the Applied readout and the log.

Saved colors do not match the screen

They should: saved frames and recordings are produced by the same palette and gamma path as the display. Confirm you are looking at the file from the same run and that it is a demo file (watermarked) or a camera file as expected.

The application closes with an error

A fatal camera or processing error ends the run rather than leaving a broken measurement. A dialog shows the exception, and the full traceback is in the run's log file under output/logs/. Restart the app and, if it recurs, include that log when asking for help.

Updates, features and Codex #

There is one Qt front end; the old Tk interface is no longer part of the application.

Automatic updates

Packaged copies check GitHub at startup and offer a newer full release (pre-releases are skipped). A blue Update available button appears in the status bar and the log. Click it to download while measurement continues; the app verifies the SHA-256, then offers to restart. It finishes any recording, releases the camera, swaps in the new build and starts it with the same options. Choosing not to restart installs the update when you close the app.

  • Check for updates in the status bar or Help → Check for updates… checks on demand; it is greyed out while a check runs. While the app stays open it also checks on its own every few hours.
  • espi-live --update updates without opening a window; --no-update-check skips the startup check and source download.
  • The program's folder must be writable. Output, token files and recordings are never touched. A single-file build from build 6 or earlier cannot update itself to the folder layout; download a current release by hand once.
  • The build number is ordered by workflow run, so a copy never updates to an older build. Running from source does not self-update; use git pull.

Request a feature

Request feature in the status bar or Help → Request a feature… asks for a title, optional description and optional name, then files a GitHub issue labelled feature-request and enrich. The issue includes the build, platform and video source. Submit files it from the app; a blank description is written from the title, and text you write is kept and expanded. A copy without a feedback token says it cannot file the request.

Open in Codex

Packaged copies keep the source they were built from in espi-live-source/ next to the program. Open in Codex in the status bar or Help → Ask Codex about the source code… opens OpenAI Codex on that folder, so you can ask how the program works. It reads Getting source… while the source downloads first. A change approved in Codex is sent as a GitHub issue with --send-changes; it is not pushed with git from the app. Running from source opens the checkout itself.
